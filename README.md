# FlowMetric

Видеоаналитика зала кафе: детекция и трекинг людей, роли «сотрудник / посетитель» и события обслуживания по видео со статичной камеры.

Пайплайн состоит из четырёх этапов:

1. YOLO11s @1280 + BoT-SORT локально детектируют людей и строят покадровые треки.
2. GPT-6 Astra на разреженных кадрах (по умолчанию 1 кадр/с, батчи по 16) переидентифицирует людей и определяет роли.
3. Локальные фрагменты объединяются в глобальные ID по IoU-сопоставлениям с Astra.
4. По траекториям, зонам камеры и опциональной карте столов извлекаются вход, выход, выход из кухни, посадка, начало/конец обслуживания и интервалы ожидания.

При синхронизации пары ниже IoU-порога исключаются до Hungarian assignment, а union-find не позволяет склеить разные Astra-ID одного батча или два одновременно видимых, пространственно разных локальных трека.

Результат — видео с разметкой, `tracks.json`, `events.json` и, при наличии эталона, `benchmark_report.json`.

## Структура

```text
track.py                  основной пайплайн и CLI
astra.py                  Astra API, проверка ответа и версионированный кэш
scene.py                  загрузка и проверка калибровки камеры/столов
events.py                 события и состояния по траекториям
metrics.py                ID, роли, события P/R/F1 и tIoU состояний
tables.py                 построение статичной карты столов
config/                   зоны камеры, карта столов, настройки трекера
benchmark/                эталон для тестового клипа
experiments/              сетка детекторов, трекеров, ReID и VLM
reports/                  пересчитанные CSV и отчёт по экспериментам
tests/                    unit-тесты метрик, событий, кэша и конфигурации сцены
data/                     входное видео и результаты прогонов
```

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
echo "VSELLM_API_KEY=..." > .env      # либо OPENAI_API_KEY
```

## Запуск

```bash
# Гибридный режим; результаты попадут в data/output/
python track.py

# Подключить заранее построенную карту столов
python track.py --tables config/tables.json

# Только локальный трекинг, без API
python track.py --no-astra

# Пересчитать метрики для существующих tracks.json/events.json
python metrics.py
```

Калибровки в `config/camera.json` и `config/tables.json` содержат разрешение исходного кадра. `scene.py` проверяет разрешение, геометрию зон и боксы столов до детекции и API-вызовов. Карта от другого имени файла допускается с предупреждением, но только если положение камеры действительно не менялось.

Карту столов можно перестроить отдельно:

```bash
python tables.py --video data/example.mp4
```

### Кэш Astra

По умолчанию ответ сохраняется в `data/output/astra_reid.json`. Это версионированный кэш с манифестом: в нём проверяются хеш и размер видео, FPS/разрешение/число кадров, выбранные кадры и батчи, модель, effort, версии prompt/schema, система координат и полнота покрытия.

- Совпадающий кэш используется повторно.
- Устаревший, повреждённый или относящийся к другому запуску кэш отклоняется; при наличии API-ключа он атомарно заменяется новым.
- Старый формат без манифеста намеренно не используется в прод-пайплайне. Без API-ключа такой запуск завершится понятной ошибкой; используйте ключ для обновления либо `--no-astra`.

Исторические Astra-ответы в `data/experiments/` по-прежнему читаются экспериментальным раннером для воспроизводимости старой сетки.

## Результаты на эталонном клипе

Метрики пересчитаны после исправления tIoU и правил событий. Основная метрика continuity и точность ролей теперь **end-to-end**: отсутствующий GT-человек получает ноль. Значение **mapped** приведено отдельно и оценивает только людей, которых удалось сопоставить с якорями; оно не подходит для самостоятельного ранжирования.

| Конфигурация | Strict F1 (P/R) | ID | Anchored | Continuity e2e / mapped | Роли e2e / mapped |
|---|---:|---:|---:|---:|---:|
| Локальный prod: YOLO11s 1280 + ultralytics BoT-SORT | 0.320 (0.250/0.444) | 67 | 28/30 | 0.632 / 0.677 | 0.933 / 1.000 |
| Тот же трекер + Astra 1 fps | **0.571 (0.421/0.889)** | 41 | 28/30 | **0.857 / 0.918** | **0.933 / 1.000** |
| YOLO11s 1280 + BoxMOT 12 BoT-SORT + Astra 1 fps | 0.571 (0.421/0.889) | 34 | 26/30 | 0.804 / 0.928 | 0.867 / 1.000 |
| Лучший результат сетки: BoostTrack BoxMOT 25 + Astra | **0.640 (0.500/0.889)** | 42 | 28/30 | 0.852 / 0.912 | 0.933 / 1.000 |
| Лучший результат сетки: OccluBoost BoxMOT 25 + Astra | **0.640 (0.500/0.889)** | 37 | 26/30 | 0.802 / 0.925 | 0.867 / 1.000 |

Две лучшие строки — результат на одном 15-секундном клипе, а не доказательство превосходства для других камер. Текущий `track.py` использует ultralytics BoT-SORT; трекеры BoxMOT 25 пока остаются экспериментальными.

Подробная методика, сравнение 222 конфигураций и таблиц — в [`reports/EXPERIMENTS.md`](reports/EXPERIMENTS.md). Для воспроизведения полной сетки нужны зависимости из `requirements-experiments.txt`.
