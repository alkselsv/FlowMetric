# Эксперименты: детекция × трекинг × ReID × GPT-6 Astra

Клип: `data/hf_*.mp4` — 15 с, 361 кадр, 1920×1080, 24 fps, 30 человек. Эталон: `benchmark/ground_truth.json` с якорями голов на кадрах 0 и 86, пятью сотрудниками, девятью событиями и интервалами состояний.

> Отчёт пересчитан после исправления метрик, правил событий и синхронизации ID. Старые значения continuity около `0.92` и ролей `100%` были условными — только по людям, сопоставленным с якорями. В текущем отчёте основные колонки считаются end-to-end, а mapped-метрики показаны отдельно.

## Объём и артефакты

- 222 конфигурации «детектор + трекер»: 138 исходных сочетаний и 84 сочетания с трекерами BoxMOT 25.
- Девять режимов на конфигурацию: local и восемь сохранённых ответов VLM. Всего 1998 строк.
- Hybrid-колонки в `experiments_summary.csv` — среднее только по трём повторам Astra 1 fps с effort `low`; запуск `medium` в это среднее не входит.
- Карта столов отдельно оценена при `TABLE_GAP` 0.2, 0.35 и 0.5.

Актуальные машинно-читаемые результаты:

- [`experiments.csv`](experiments.csv) — каждый прогон;
- [`experiments_summary.csv`](experiments_summary.csv) — одна строка на конфигурацию;
- [`experiments_tables.md`](experiments_tables.md) — полная ранжированная таблица;
- `experiments*_tablegap{0.2,0.35,0.5}.csv` и соответствующие Markdown-таблицы — варианты со столами.

## Как теперь считаются метрики

| Метрика | Определение |
|---|---|
| Anchor recall | Доля GT-голов, найденных детектором на двух опорных кадрах при conf ≥ 0.3 |
| Anchor coverage | Доля из 30 GT-людей, которым удалось назначить предсказанный ID |
| Continuity e2e | Средняя доля ожидаемого присутствия всех GT-людей, покрытая их главным ID; несопоставленный человек получает 0 |
| Continuity mapped | Та же величина только на сопоставленном подмножестве; читать вместе с anchor coverage |
| Роли e2e / mapped | Точность staff/customer по всем 30 людям / только по сопоставленным людям |
| Strict F1 | Совпали тип события, участники после ID mapping и время ±1 с |
| Loose F1 | Совпали тип и время ±1 с, участники не проверяются |
| Waiting/consuming tIoU | IoU объединений временных интервалов; пересечения не учитываются дважды, интервалы unmapped-ID остаются false positive |

Колонки `continuity`, `continuity_staff` и `role_acc` в CSV — end-to-end. Условные значения записаны явно как `continuity_mapped` и `role_acc_mapped`.

### Что исправлено перед пересчётом

- tIoU теперь работает с объединениями интервалов и всегда остаётся в диапазоне `[0, 1]`.
- GT-ID больше не предполагаются непрерывным диапазоном `1..30`; несопоставленные GT-люди штрафуют continuity и роли.
- У событий обслуживания сохраняется конкретный customer ID: переключение сотрудника с одного клиента на другого больше не склеивается в один эпизод. Проверяются минимальная длительность, число наблюдений и покрытие трека.
- Клиент, появившийся в середине видео, становится доступен для обслуживания только после наблюдаемой посадки; `leave_kitchen` создаётся только для staff; короткий разреженный хвост трека больше не считается уверенным выходом.
- Перед Hungarian assignment отбрасываются пары с IoU ниже порога. Union-find запрещает объединять разные Astra-ID из одного батча и локальные треки, которые одновременно видны как пространственно разные люди; почти совпадающие вложенные дубли не блокируют склейку.

## Главные результаты

На исходных 138 конфигурациях переход с local на Astra 1 fps даёт в среднем:

| Метрика | Local | Astra 1 fps, low |
|---|---:|---:|
| Strict F1 | 0.210 | 0.352 |
| Precision / recall | 0.172 / 0.276 | 0.267 / 0.517 |
| Continuity e2e | 0.485 | 0.664 |
| Continuity mapped | 0.642 | 0.874 |
| Staff continuity e2e | 0.505 | 0.672 |
| ID | 59.3 | 39.7 |
| Роли e2e / mapped | 0.725 / 0.954 | 0.734 / 0.965 |
| Waiting tIoU | 0.160 | 0.311 |
| Consuming tIoU | 0.426 | 0.594 |

То есть Astra заметно улучшает склейку ID, события и состояния, но mapped-колонки показывают более оптимистичную картину, чем реальная полнота системы.

### Лучшие конфигурации без карты столов

Hybrid здесь усреднён по трём Astra low-повторам.

| Конфигурация | ID | Coverage | Continuity e2e / mapped | Роли e2e / mapped | Strict P / R / F1 |
|---|---:|---:|---:|---:|---:|
| YOLO11s 1280 + BoostTrack BoxMOT 25, наши пороги | 42.3 | 0.933 | 0.852 / 0.912 | 0.933 / 1.000 | 0.500 / 0.889 / **0.640** |
| YOLO11s 1280 + OccluBoost BoxMOT 25, наши пороги | 37.0 | 0.867 | 0.802 / 0.925 | 0.867 / 1.000 | 0.500 / 0.889 / **0.640** |
| YOLO11s 1280 + SFSORT BoxMOT 25, наши пороги | 43.3 | 0.867 | 0.798 / 0.920 | 0.867 / 1.000 | 0.471 / 0.889 / 0.615 |
| YOLO11s 1280 + ByteTrack (BoxMOT 12) | 42.0 | 0.933 | 0.863 / 0.925 | 0.933 / 1.000 | 0.462 / 0.889 / 0.608 |
| YOLO11s 1280 + ultralytics BoT-SORT (prod) | 41.7 | 0.933 | 0.857 / 0.918 | 0.933 / 1.000 | 0.421 / 0.889 / 0.571 |
| YOLO11s 1280 + BoT-SORT BoxMOT 12, без ReID | 34.0 | 0.867 | 0.804 / 0.928 | 0.867 / 1.000 | 0.421 / 0.889 / 0.571 |

Лидеры BoostTrack и OccluBoost имеют одинаковые 8 TP, 8 FP и 1 FN. У prod-конфигурации — 8 TP, 11 FP и 1 FN. Лишние `service_start/service_end` остаются главным источником ошибок; на одном коротком клипе разница одного события заметно меняет F1.

### Практический выбор

- `track.py` сейчас использует ultralytics BoT-SORT. С Astra 1 fps отдельный low-запуск даёт 41 ID, coverage 28/30, continuity `0.857 / 0.918` e2e/mapped, роли `0.933 / 1.000` и strict F1 `0.571` (`P=0.421`, `R=0.889`).
- BoxMOT 12 BoT-SORT без ReID даёт столько же событий, но 34 ID и меньшую e2e-полноту: coverage 26/30, continuity `0.804 / 0.928`.
- BoxMOT 25 BoostTrack/OccluBoost с нашими порогами лидируют в сетке, но пока не встроены в основной CLI. Разница получена на одном клипе и требует проверки на других камерах.
- Если Astra недоступна, Hybrid-SORT BoxMOT 25 остаётся сильным локальным вариантом: в среднем по шести детекторам local F1 `0.363` на родных порогах и `0.356` на наших. Astra почти не улучшает его из-за уже сделанных внутри трекера склеек.

## Детекторы, трекеры и ReID

Среди исходных трекеров лучший детектор — YOLO11s 1280: средний hybrid F1 `0.561` и continuity e2e `0.831`. Для сравнения, YOLO11s 640 даёт `0.257` и `0.495`; увеличение модели при 1280 не обеспечивает стабильного выигрыша относительно YOLO11s.

Внешние ReID-модели у BoT-SORT не окупают задержку. В среднем по 14 детекторам:

| BoT-SORT | Track ms на YOLO11s | Local continuity | Hybrid continuity | Local / hybrid F1 |
|---|---:|---:|---:|---:|
| Без ReID | 1.4 | 0.473 | 0.612 | 0.211 / 0.308 |
| OSNet x0.25 | 24.6 | 0.473 | 0.619 | 0.211 / 0.322 |
| OSNet x1.0 | 65.3 | 0.469 | 0.618 | 0.211 / 0.311 |
| CLIP-ReID | 220.8 | 0.463 | 0.611 | 0.189 / 0.300 |

Задержка в таблице показана для YOLO11s 1280, а качества — среднее по всем 14 детекторам. Небольшие различия качества на единственном клипе меньше экспериментальной неопределённости.

У RF-DETR без дообучения остаются проблемы с дальними людьми и шкалой confidence. Калибровка и разрешение 1024 помогают, но YOLO11s 1280 по-прежнему даёт лучший баланс качества и скорости. Полные значения по каждому детектору находятся в [`experiments_tables.md`](experiments_tables.md).

## Карта столов

`tables.py` агрегирует COCO-детекции столов по видео, а `scene.py` проверяет разрешение и геометрию карты. В основном CLI карта включается явно:

```bash
python track.py --tables config/tables.json
```

С картой клиент должен иметь домашний стол, а сотрудник — находиться рядом с этим столом. Карта не включается по умолчанию, потому что влияние порога зависит от сцены.

Изменения относительно тех же конфигураций без столов, в среднем по 222 конфигурациям:

| TABLE_GAP | ΔF1 local | ΔF1 hybrid | ΔP / ΔR hybrid | ΔWaiting tIoU | Prod hybrid F1 | Лучший F1 |
|---:|---:|---:|---:|---:|---:|---:|
| 0.2 | +0.017 | **−0.073** | −0.031 / −0.168 | −0.093 | 0.500 | 0.588 |
| 0.35 | +0.015 | **+0.018** | +0.024 / −0.003 | −0.044 | **0.571** | **0.615** |
| 0.5 | +0.010 | +0.014 | +0.017 / +0.001 | +0.009 | 0.533 | **0.615** |

При 0.35 hybrid F1 растёт у 57.7% конфигураций и падает у 18.5%, но у prod-конфигурации остаётся `0.571` — как без столов. Порог 0.2 слишком строг и режет recall; 0.5 в среднем слегка помогает, но ухудшает prod F1 до `0.533`. Ни один вариант со столами не превзошёл лучший результат без них (`0.640`), поэтому карту следует считать сценоспецифичным дополнительным сигналом, а не новым дефолтом.

Лучший результат при 0.35 и 0.5 — YOLO11s 1280 + BoostTrack BoxMOT 25 с нашими порогами: F1 `0.615`, continuity e2e `0.852`. При 0.2 формальный лидер — YOLO26s 1280 + OccluBoost на родных порогах с F1 `0.588`, но coverage всего `0.400` и continuity e2e `0.368`; это хороший пример того, почему одну событийную метрику нельзя читать без end-to-end полноты.

## Надёжность пайплайна

- Конфигурации камеры и столов привязаны к разрешению; несовпадение останавливает запуск до детекции и API-вызовов.
- Прод-кэш Astra содержит версию, SHA-256/размер видео, параметры видео и семплирования, модель/effort, версии prompt/schema и координатные метаданные. Неподходящий или legacy-кэш отклоняется и при наличии ключа заменяется атомарно.
- Ответы Astra проверяются семантически: ID, роли, кадры, уникальность детекций, конечные и упорядоченные координаты, размеры и полное покрытие ожидаемых батчей.
- Экспериментальные кэши жёстко привязаны к имени benchmark-видео; раннер отказывается применять их к другому источнику.
- `--stages eval` не декодирует всё видео в память, если нужны только сохранённые детекции/треки и пересчёт метрик.

## Ограничения

- Один клип, 30 человек и 9 событий. Разницу меньше примерно `0.1` F1 нельзя считать убедительной без новых видео.
- Правила зон и событий настраивались на этой камере, поэтому возможна подгонка.
- Якоря есть только на двух кадрах. Mapped-метрики условны, а end-to-end метрики смешивают ошибки детектора, anchoring и трекинга — это намеренно отражает качество всей системы.
- Ответы VLM сохранены заранее: сравнение трекеров использует одинаковые ответы, но не измеряет вариативность новых API-вызовов сверх трёх low-повторов.
- Карта столов получена автоматической детекцией и содержит геометрические неточности; для реальной установки лучше ручная калибровка.
- Скорость измерена на Apple Silicon (MPS), FP32, batch 1, без TensorRT/FP16.

## Воспроизведение

```bash
pip install -r requirements-experiments.txt
pip install --no-deps boxmot==12.0.2

# Сохранённые ответы VLM (нужен API-ключ только при новом запросе)
python experiments/astra_variants.py

# Полная сетка или только безопасный пересчёт из кэшей
python experiments/run_experiments.py
python experiments/run_experiments.py --stages eval

# Карта столов и повторная оценка
python tables.py
python experiments/run_experiments.py --stages eval --table-gap 0.35

# Unit-тесты
.venv/bin/python -m unittest discover -s tests -v
```

Для BoxMOT 25 использовался отдельный checkout и `experiments/boxmot25_tracks.py`; он не является зависимостью основного `track.py`.
