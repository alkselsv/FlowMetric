# Benchmark: эталон для клипа `data/hf_*.mp4`

Источник исходной разметки: [nofriendsatall/video_analytics](https://github.com/nofriendsatall/video_analytics).

| Файл | Что это |
|---|---|
| `Timings.txt` | Сотрудники, события с таймингами и интервалы потребления |
| `First.png`, `Second.png` | Кадры 0 и 86 с номерами людей над головами |
| `ground_truth.json` | Якоря голов в координатах 1920×1080, роли, события и состояния |

Запуск оценки:

```bash
python metrics.py \
  --tracks data/output/tracks.json \
  --events data/output/events.json \
  --gt benchmark/ground_truth.json
```

`metrics.py` сначала связывает GT-людей с предсказанными ID по якорям на кадрах 0 и 86, затем считает:

- `continuity_mean` — end-to-end покрытие присутствия всех GT-людей одним главным ID; несопоставленные люди дают ноль;
- `continuity_mapped` — та же величина только для сопоставленных людей, вместе с coverage;
- точность ролей end-to-end и условную точность только на mapped-подмножестве;
- strict события (тип + участники + время ±1 с) и loose события (тип + время);
- tIoU ожидания/потребления как IoU объединений временных интервалов без двойного учёта перекрытий. Интервалы несопоставленных предсказанных ID остаются false positive, а не исчезают из оценки.

Поэтому старые значения continuity `0.92` и ролей `100%`, рассчитанные только на сопоставленных людях, нельзя напрямую сравнивать с основными end-to-end колонками новых CSV.

## Контракт service FSM

Обслуживание больше не определяется одним геометрическим условием. Для обычного кандидата FSM требует наблюдаемое приближение именно сотрудника за окно 1.5 с, вход в зону не дальше 0.9 высоты его бокса, остановку для захвата пары и достаточную долю стационарных наблюдений (`0.72`) на всём подтверждаемом интервале. Финальный gate приближения требует уменьшения расстояния не менее чем на 0.18 высоты бокса; left-censored кандидат первого кадра — явно помеченное исключение без наблюдаемого подхода. Один сотрудник может обслуживать не более одного клиента, и один клиент не может одновременно принадлежать двум сотрудникам.

Завершение подтверждается не менее чем 0.3 с движения сотрудника и ростом расстояния либо выходом из tight-зоны. Расширенная зона 1.1 используется как дополнительное свидетельство ухода и как гистерезис повторного взведения пары. Разрывы до 0.5 с считаются дрожанием трека и объединяются с тем же эпизодом. После конца блокируется только эта пара сотрудник–клиент: повторное срабатывание разрешается после выхода из расширенной зоны либо после 1.5 с отсутствия наблюдений. Это не мешает сотруднику перейти к другому клиенту или другому сотруднику обслужить прежнего клиента.

`events.json` содержит два представления:

- `events` — наблюдаемые точечные `service_start/service_end`, на которых считаются strict/loose event-метрики;
- `service_intervals` — полные эпизоды с `left_censored`, `right_censored` и эвристическим `confidence`. Confidence полезен для ранжирования, но не является калиброванной вероятностью.

Контракт ориентирован на precision. Если взаимодействие уже шло на первом кадре, его начало неизвестно: left-censored кандидат остаётся только в `service_intervals` и не публикует ни одного point event, поэтому `events` и событийные метрики его не учитывают. Если взаимодействие началось в кадре, но не закончилось до конца наблюдения, right-censored интервал публикует наблюдаемый `service_start` с флагом `right_censored`, но не `service_end`.

Все численные пороги FSM подобраны на этом единственном dev-клипе. До использования как универсальных дефолтов их необходимо проверить на held-out видео, других камерах и плотностях посетителей.

Актуальные результаты и ограничения одного короткого клипа описаны в [`../reports/EXPERIMENTS.md`](../reports/EXPERIMENTS.md).
